# Policy assumptions register

**Status of every entry below: UNRESOLVED — documented assumption, not approval.**
Pinterest has not been asked and has not answered any of these. The product is built against them so work is not blocked; each one is enforced through a named config switch so the behaviour can be tightened without a schema change if the answer turns out to be "no".

Rules for contributors and agents:
1. Never change an entry's status to approved/resolved without a dated written source pasted under it.
2. Code that depends on an assumption cites its ID in a comment (`// policy: PA-01`) and reads the switch named here.
3. Marketing copy, UI and docs must not state or imply that Pinterest has approved PinPulse, its storage practices or its integrations.
4. These assumptions never relax the hard controls: tenant isolation (RLS), per-workspace consent records, envelope encryption of tokens, read-only scopes, and purge on disconnect.

| PA-01 | Daily snapshots of a consenting account's own organic analytics (numbers only) may be stored for up to 90 days raw and 13 months derived, to provide the service to that account holder. | Developer Guidelines: "you may not store any information accessed through any Pinterest Materials including the API"; Terms §4.1(a) exception for "campaign analytics information" about an account whose holder "has expressly granted you access". | `RETENTION_RAW_DAYS` (default 90), `RETENTION_DERIVED_DAYS` (default 395); `src/modules/privacy/retention.ts` | Set `RETENTION_RAW_DAYS=0` (metrics fetched per analysis run and discarded), keep derived outputs only if separately allowed, rely on user-uploaded CSV exports for history (`/drop-check`, CSV import). |
| PA-02 | Minimal Pin metadata (Pin id, created_at, board id, link URL, link domain, declared AI disclosure) may be stored alongside metrics; titles, descriptions, images and board names are never stored. | Same storage clause. | `STORE_PIN_METADATA` (default true); `pin_meta` table; schema test forbids title/description/image columns | Fetch metadata on demand per analysis run; drop `pin_meta`. |
| PA-03 | A perceptual hash of the user's own Pin images may be computed transiently; only duplicate-cluster membership is persisted. | Same storage clause; Guidelines on creating content from Pins. | `PERSIST_IMAGE_HASHES` (default false); analytics `/v1/duplicates` | Compute clusters per run only; persist nothing. |
| PA-04 | Comparing an account against Pinterest's own published guidance (e.g. load time under 4 s, crawl-delay ≤ 1) and against its own history is not "platform insights, benchmarking, or competitor research". | Guidelines: no "platform insights, benchmarking, or competitor research features" without written authorization. | Pre-flight and integrity rules are labelled `official` / `vendor` / `hypothesis`; no cross-account comparison exists in code | Remove threshold language that reads as a benchmark; keep own-history comparisons only. |
| PA-05 | An agency may monitor a client's account when the client completes PinPulse's consent flow and authorizes via Pinterest OAuth; this satisfies "expressly granted you access". | Terms §4.1(a); Guidelines "Don't combine someone's account information with information from other people's accounts". | `consent_record` per workspace (scopes, consent text version, timestamp); RLS per workspace; no cross-client aggregation queries | Restrict agency mode to accounts the agency itself owns, or require client-side PinPulse accounts. |
| PA-06 | A "weather" index built only from voluntary user-reported onset dates and symptoms (no Pinterest API data) is not combining account information or providing platform insights. | Guidelines combining and benchmarking clauses. | `WEATHER_SOURCE=user_reports` (only value implemented); API metrics are never read by the weather module (enforced by module boundary test) | Unpublish the public weather page; keep reports private to the reporter. |
| PA-07 | Fetching the user's own landing pages with Pinterestbot user-agent strings, at ≤ 1 request/s per domain and with an honest `X-PinPulse-Check` header, is acceptable to diagnose Visit-site eligibility. | Pinterestbot help page; site owners' terms. | `INTEGRITY_UA_MODE` (`pinterestbot` default, `honest` alternative); domain allowlist = tenant's own link domains and claimed sites; SSRF guard | Switch to `honest` UA only; report robots.txt results by parsing rather than by fetching as the bot. |
